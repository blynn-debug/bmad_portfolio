# PRD Addendum — Flutter Showcase Museum

> PRD 본문에 들어가기엔 구현/기술 레벨이거나 다운스트림 문서(아키텍처·UX·빌드 계획)에 속하는 내용. 의사결정 근거 보존용.

## 기술 메커니즘 / How (→ 아키텍처)

- **3종 스플릿 뷰:** MaterialApp + CupertinoApp을 한 화면에 공존시키려면 위젯 트리 분리가 필요. 단일 `MaterialApp` 하위에 영역별로 `Theme`/`CupertinoTheme`를 격리하는 방식 vs 다중 App 위젯 중첩 — PoC로 검증 필요.
- **리빌드 가시화:** Flutter 렌더링 파이프라인 훅 기반 히트맵은 초보 범위 초과. MVP는 위젯별 `build` 호출 카운터 표시로 대체. 히트맵은 stretch.
- **영속성:** 로컬 저장(키-값 또는 경량 DB)으로 진행 상태·튜닝값 저장. Stage 8이 영속성 자체를 학습 주제로 삼으므로 저장방식 토글 비교가 학습 콘텐츠이자 인프라.
- **발현 파이프라인:** 슬라이더/토글/드래그 → 튜닝값(상태) → 영속 저장 → 로비 위젯 반영. Custom 탭 값이 발현 소스.

## 빌드 전략 (→ 빌드 계획)

- **순서:** 로비 인프라 → Stage 1 레이아웃 실험실(킬링 포인트 검증) → 데이터 저장(영속성 토대) → 나머지 스테이지.
- **핵심 마일스톤:** Stage 1 완성 = 프로젝트 생사 결정. 핵심 루프(만지기→비교→발현) 동작 확인.
- **타임라인:** 3-4주 (AI 협업 전제).
- **역할 분담:** AI = 구현/구조, sy = 체험/미감 판단/환경 셋업.
- **배포:** Xcode 실기기 직접 빌드. 무료 계정 7일 재설치 제약 감수.

## 거부된 대안 & 근거

- **Web-only 배포** → 거부: 생체인증·키체인·알림 등 네이티브 체험 불가.
- **24개 스테이지** → 거부: 스코프 폭발, "한 번에 완성" 제약 위반.
- **모든 스테이지 3종 비교** → 거부: 상태관리·제스처 등 의미 없는 영역 과적용.
- **동일 인터랙션 패턴 반복** → 거부: 반복 피로 유발 → 영역별 인터랙션 변주로 대체.
- **감성적/짧은 헤드라인** → 거부: 킬링 포인트 둘 다 담는 구체적 차별화 선호.

## 경쟁 정보 (→ 포지셔닝 근거)

- Flutter Gallery 2024 아카이브 → 위젯 쇼케이스 공백.
- Flutter 2026 Material/Cupertino 코어 분리 진행 중 → 이 분리를 가르치는 도구 부재(타이밍 우위).
- DartPad: 코드 에디터, 인터랙티브 속성 조작 불가.
- Widgetbook: 개발자 도구, knobs는 있으나 교육 내러티브 없음.
- Swift Playgrounds: 가장 가까운 유사 사례지만 "탐색이 곧 앱" 모델 아님.
- side-by-side 디자인 시스템 비교 + 인터랙티브 속성 조작 + 탐색-건설 융합을 모두 결합한 도구는 부재.
