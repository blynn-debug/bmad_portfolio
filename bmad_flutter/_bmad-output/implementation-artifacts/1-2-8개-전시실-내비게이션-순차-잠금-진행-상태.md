# Story 1.2: 8개 전시실 내비게이션 & 순차 잠금/진행 상태

Status: done

## Story

As a 학습자,
I want 로비에서 8개 전시실로 이동하되 순서대로 잠금이 풀리는 것을 보고,
So that "성장하는 박물관" 흐름을 따라 한 스테이지씩 진행할 수 있다.

## Acceptance Criteria

**AC1 (FR2)** — 8개 전시실 진입점 표시
- **Given** 로비가 표시된 상태에서
- **When** 전시실 목록을 본다
- **Then** 8개 전시실(스테이지) 진입점이 로비에 표시된다

**AC2 (FR3)** — 초기 순차 잠금
- **And** 첫 스테이지(Stage 1 레이아웃)만 열려 있고 나머지 7개는 잠겨 있다
- **And** 잠긴 전시실은 시각적으로 구분되고(예: 자물쇠 표시) 진입이 차단된다

**AC3 (FR3, FR4)** — 클리어 시 다음 해제 & 로비 반영
- **When** 한 스테이지를 클리어한다
- **Then** 바로 다음 스테이지가 해제된다
- **And** 클리어/잠금 상태 변화가 로비에 즉시 반영된다(클리어 표시 + 다음 칸 해제)

**AC4 (진행 상태 단일 관리 — Story 1.4 영속 대비)** — 단일 진도 상태
- **And** 진행 상태는 전역 단일 SSOT(`MuseumState`)로 관리되어, 이후 Story 1.4의 영속 인프라가 그대로 직렬화/복원할 수 있는 형태(`toJson`/`fromJson` 가능)로 보관된다
- **And** (이 스토리 범위에서는) 실제 디스크 영속은 하지 않는다 — 재시작 시 초기 상태로 돌아가는 것은 정상이다(영속은 Story 1.4)

## Dev Notes

### 핵심 컨텍스트
이 스토리는 Epic 1 수직 슬라이스에서 **"성장하는 박물관"의 진행 골격**을 세운다. 산출물은 (1) 전역 상태 인프라(`MuseumState` + Provider 주입), (2) 8개 전시실 내비 + 순차 잠금 UI, (3) 클리어→해제 흐름. 실험실 콘텐츠/발현/영속은 포함하지 않는다. 이후 모든 스토리(1.3 발현 프레임, 1.4 영속, 1.5+ 스테이지)가 여기서 만든 `MuseumState`를 토대로 쌓인다.

### 🚨 스코프 경계 (절대 넘지 말 것)
이 스토리는 **내비게이션 + 진행 상태 인프라만** 한다. 다음은 후속 스토리 범위이므로 **여기서 구현 금지**:
- ❌ shared_preferences 실제 영속 / `MuseumRepository` / `prefs_keys.dart` → **Story 1.4** (이 스토리는 in-memory 상태 + toJson/fromJson 훅까지만)
- ❌ 실험실 공통 프레임 `LabScaffold` / "발현하기" 액션 / 발현 연출 → **Story 1.3** (이 스토리의 `StagePlaceholderScreen`은 임시 스텁)
- ❌ 실제 스테이지 콘텐츠(슬라이더/토글/드래그 등) `stages/*` → **Story 1.5+**
- ❌ 3종 비교 / Custom 테마 / `comparison_view` → **Story 1.6/1.7**
- ❌ `lobby/manifestations/*` 발현물 위젯 → 각 스테이지 발현 스토리

진행 상태의 **실제 디스크 영속이 없는 것은 의도된 것**이다(AC4). 재시작 시 초기화되는 것은 1.4에서 해결한다. 단, 상태 형태는 1.4가 바로 직렬화할 수 있게 `toJson`/`fromJson`을 갖춘다.

### 아키텍처 준수 — 상태/내비게이션 규칙 (반드시 따를 것)
[Source: architecture.md#Frontend Architecture, #Structure Patterns, #Communication Patterns, #Enforcement Guidelines]
- **상태관리 = Provider.** 전역 상태는 `ChangeNotifier` 1급 클래스(`MuseumState`). 위젯은 `context.watch<T>()`/`Consumer`로 구독, 액션은 `context.read<T>()`로 호출. `Provider.of(listen:false)` 대신 `read` 일관 사용.
- **`notifyListeners()`는 상태 변경 직후 1회만.** 루프 내 다발 호출 금지. 변화 없으면(중복 clear) 호출하지 않음.
- **불변 업데이트:** 컬렉션은 새 인스턴스로 교체 후 notify(`StageProgress.withCleared`가 새 인스턴스 반환).
- **단방향 파이프라인:** UI 액션 → `MuseumState` 메서드 → (1.4부터 영속) → notify → Consumer 리빌드. UI가 상태를 우회해 직접 변경 금지.
- **내비게이션 = Navigator 1.0**(`MaterialPageRoute`). 순차 잠금은 "상태 기반 진입 가드" — 잠긴 스테이지는 push 자체를 막는다.
- **즉각 피드백 vs 전역 커밋:** 실험실 로컬 미리보기는 setState(후속 스토리), 전역 커밋은 발현 시점. 본 스토리의 "클리어"는 진행 상태 전역 커밋이므로 `MuseumState` 경유가 맞다.
