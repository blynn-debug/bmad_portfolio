# Story 1.3: 공통 실험실 프레임 & 발현 액션

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a 학습자,
I want 모든 실험실이 공유하는 "상단 미리보기 + 하단 조작" 틀과 "발현하기" 동작을,
so that 어느 스테이지에 들어가도 일관된 방식으로 만지고 결과를 로비에 반영할 수 있다.

## Acceptance Criteria

**AC1 (FR5, NFR4)** — 공통 실험실 프레임 + 즉각 피드백
- **Given** 한 스테이지(실험실)에 입장한 상태에서
- **When** 하단 조작 패널을 조작한다
- **Then** 상단 미리보기가 지연 없이(로컬 setState) 즉시 갱신된다
- **And** 모든 실험실은 동일한 레이아웃(상단 결과 미리보기 영역 + 하단 조작 패널)을 따른다

**AC2 (FR6, FR7)** — 발현하기 액션 + 로비 반영 + 클리어 연출
- **Given** 스테이지 학습 조건을 충족한 상태에서(예: 조작을 1회 이상 수행)
- **When** "발현하기"를 실행한다
- **Then** 해당 스테이지의 산출물이 로비 발현물 영역에 발현된다(빈 상태 안내 → 발현물 카드)
- **And** 발현 버튼 등장/실행에 단순 스케일/페이드 연출이 적용되어 클리어가 표시된다
- **And** 발현은 전역 `MuseumState`를 경유한 단일 커밋이며, 발현 시 해당 스테이지가 클리어되어 다음 스테이지가 해제된다(FR3 진행 흐름과 통합)

**AC3 (FR8)** — 인터랙션 위젯 슬롯 주입 설계
- **And** 공통 프레임(`LabScaffold`)은 영역별로 다른 인터랙션 위젯(슬라이더/토글/드래그/시나리오/자유)을 **미리보기 슬롯**과 **조작 슬롯**으로 끼울 수 있도록 슬롯 주입 방식으로 설계된다
- **And** `LabScaffold`는 특정 스테이지에 의존하지 않는다(스테이지 비의존 재사용 프레임 — `lib/shared/`)

**AC4 (발현 조건 게이팅 — FR6)** — 학습 조건 충족 전 발현 차단
- **Given** 아직 학습 조건을 충족하지 않은 상태에서
- **Then** "발현하기"는 노출되지 않거나(숨김/페이드아웃) 비활성이어서 실행할 수 없다
- **When** 조건을 충족하면
- **Then** 발현 버튼이 스케일/페이드 연출과 함께 나타난다

## Dev Notes

### 핵심 컨텍스트
이 스토리는 Epic 1 수직 슬라이스의 **실험실→발현 공통 루프 골격**을 세운다. 산출물은 (1) 스테이지 비의존 공통 프레임 `LabScaffold`(상단 미리보기 + 하단 조작, 슬롯 주입), (2) 발현 버튼 `ManifestButton`(스케일/페이드 연출 + 조건 게이팅), (3) 전역 발현 액션 `MuseumState.manifest`, (4) 로비 발현물 영역 `LobbyManifestations`(발현 파이프라인 가시화). 1.2의 임시 `StagePlaceholderScreen`은 이 프레임을 호스트하는 제네릭 데모 화면 `StageLabScreen`으로 교체된다.

이후 모든 스테이지 스토리(1.5 슬라이더, 1.7 발현/프리셋, 2.x 토글/드래그 등)는 여기서 만든 `LabScaffold`/`ManifestButton`/`manifest`를 슬롯에 끼워 재사용한다.

### 🚨 스코프 경계 (절대 넘지 말 것)
이 스토리는 **공통 프레임 + 발현 액션 인프라만** 한다. 다음은 후속 스토리 범위이므로 **여기서 구현 금지**:
- ❌ 실제 스테이지 학습 콘텐츠(슬라이더로 Container/Row/Column 조작 등) → **Story 1.5+** (`lib/stages/*`). 이 스토리의 `StageLabScreen`은 프레임 동작을 증명하는 제네릭 데모일 뿐.
- ❌ 3종 플랫폼 비교 / `comparison_view` / `comparison_panel` / Custom 테마 → **Story 1.6/1.7**.
- ❌ shared_preferences 실제 영속 / `MuseumRepository` / `prefs_keys.dart` → **Story 1.4** (이 스토리는 in-memory 상태 + 기존 toJson/loadFromJson 훅 유지만).

### 아키텍처 준수 — 발현 파이프라인 / 상태 규칙 (반드시 따를 것)
[Source: architecture.md#Frontend Architecture, #Structure Patterns, #Communication Patterns, #Architectural Boundaries, #Enforcement Guidelines]
- **즉각 피드백 vs 전역 커밋:** 실험실 로컬 미리보기는 `StatefulWidget` + `setState`(지연 0, NFR4). 전역 커밋(발현)은 "발현하기" 시점에만 `MuseumState.manifest` 1회. UI가 상태를 우회해 직접 변경 금지.
- **발현 파이프라인 단방향:** UI 액션(발현 버튼) → `MuseumState.manifest` → notify → 로비 `Consumer`/`watch` 리빌드(LobbyManifestations). (영속은 1.4에서 이 사이에 끼워짐, AR3.) UI가 영속/상태를 우회 금지.
- **상태관리 = Provider.** 위젯은 `context.watch<MuseumState>()`로 구독, 액션은 `context.read<MuseumState>().manifest(...)`로 호출. `notifyListeners()`는 변경 직후 1회만, 변화 없으면(중복 발현) 호출 안 함.
- **컴포넌트 경계:** `lib/shared/`(LabScaffold/ManifestButton)는 스테이지·MuseumState 비의존 재사용 프레임 — 발현은 콜백(`onManifest`)으로 위임받아 호출처(StageLabScreen)가 MuseumState를 read. shared가 특정 stage/state를 import 하지 않는다.
- **내비게이션 = Navigator 1.0**(`MaterialPageRoute`). 진입 가드(순차 잠금)는 1.2 그대로.
